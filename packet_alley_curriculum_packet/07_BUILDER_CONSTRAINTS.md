# Builder setting: requirements, defaults, and change control

This document follows the `builder-setting` convention: hard requirements, reference defaults and project decisions. **No app code has been changed here.** Agent must treat Packet Alley's own `BUILDER-SPEC.md` as authoritative and stop on conflict.

## Retained requirements (R1–R9)

- R1: All networking, scoring, lesson progression, deterministic variant selection, prediction validation and state transitions live in `crates/core`. Rust tests exercise them without browser.
- R2: Core has no filesystem, network, browser, clock or randomness I/O. The core uses seeded, reproducible case variants computed from passed values.
- R3: Core dependencies remain on explicit allowlist. Do not add a package casually.
- R4: Public APIs consume/produce serializable values; errors are explicit.
- R5: Wasm shim only marshals values; no branching decisions or pedagogy rules.
- R6: Static HTML/CSS/JS renders values, binds interactions and accessibility, but does not determine whether reasoning is correct.
- R7: Default page stays same-origin and offline, simulates no real network I/O.
- R8: `./scripts/check.sh` remains the single predeploy command and CI uses it.
- R9: Follow nine-stage agent procedure and do not self-authorize deployment.

## New instructional constraints (PA1–PA16)

## Reference defaults

- `data/verbatim_story_copy.json` provides canonical new story/UI prompts.
- `data/level_blueprints.json` is the per-level instructional contract.
- `data/textbook_extracts.json` is **generated** and versioned with content provenance; it has no network fetch at page load.
- `scripts/extract_textbook.py` runs **offline from a cached source OR during developer build time only** and fails if a listed passage is missing.
- Existing `data/levels.json` retains node/edge and level IDs except for audited additions to fields (`lesson`, `prediction`, `proof`, `variant`, and so forth).

## Explicitly out of scope

No active DoS/SYN-flood mechanic, no spoofing or packet-injection to a real address, no live external requests from browser or Rust core, no login, no analytics, no autogenerated educational explanations, no changes to the overall chapter count, no unreviewed upload or deployment.

## Change request / SECOND-ORDER format

Record `requirement ID | original design | discovered blocker | proposed change | technical consequence | tests | professor approval` before a deviation. A task failing a requirement does not grant permission to weaken it.
